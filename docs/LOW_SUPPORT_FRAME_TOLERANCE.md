# 单帧 SfM 支持不足的最小容错修改

日期：2026-10-17。场景：`A1646-2-R4-0918` 在 `frame_000075.jpg` 的源头实例约束阶段因目标观测少于6点停止。

## 分析与取舍

检查发生在 SAM2 已完成整段视频双向传播之后。“6点”用于构造 SfM 提示和裁剪框，不是相机注册的最低点数。已注册188帧，第75帧仍有2091个全场景三维观测，但属于所选目标实例的观测少于6点。不能因此认定整段视频不可重建，也不能据这一次失败断言后续没有其他弱支持帧。

最小方案不删除图像，不扩大训练输入接口，不改训练、对齐、LABEL 或导出算法，也不添加新的投影、光流或模型。少于6个目标观测时，保留**本次已计算的 SAM2 传播掩码**，跳过当前帧的 SfM 提示细化，保留相同的魔方投影区域限制，记录警告并继续。不会把植株写为全背景，也不会从历史运行中读取旧掩码。

这会弱化这些帧的分割端邻株过滤；不能宣称保留的传播结果已经通过 SfM 正负提示检查。对应报告将 `positive_hit`、`negative_hit` 写为 null，单独标记回退模式。正常帧的正提示命中率0.8、负提示误入率0.1，以及全场景主实例选择、初始化目标一致性检查均不改变。最终点云导出仍保留原有 `TARGET_SPATIAL_RADIUS=0.8` 的空间清理；不能保证接触或重叠的邻株一定能由空间清理完全分离。

## 生产代码改动

1. `scripts/mask_generation/instance_mask_guard.py`：把单帧少于6点的异常改成记录警告并保留传播掩码；报告增加 `low_support_policy`、`low_support_frames`、每帧 `mode` 和原始 `observed_target_support`。原有 `positive_points` 仍表示抽样后的提示点数量。
2. `scripts/validate_semantic_inputs.py`：除当前实现哈希外，只额外接受已知严格旧版哈希 `1492fa2e4fb0a6bc10711e6ce51a7acceeafb18d16f7a9d8d50bd454865f043b`，以保持两个已完成场景的可复用性。未知实现哈希、图像变更、掩码变更和绑定不匹配仍然拒绝。

`run_batch_gpu1.sh`、`train.py`、`render.py` 和 `scripts/export_target_gaussians.py` 未修改。没有改0.8空间半径、训练迭代次数或其他算法阈值。

## 逻辑核对与部署

`scripts/test_mask_instance_guard.py` 增加 CPU 回归覆盖：0/1/5点不终止、不丢失植株监督，魔方区域限制保留；6点仍走原有细化；弱支持帧之后仍继续处理正常帧；已知严格旧版记录保持兼容，未知实现和被改写的掩码仍拒绝。使用临时目录和预测器替身，不加载神经网络模型、不进行视频推理或训练。

本次修改不自动重跑失败场景，不改写已有掩码、语义初始化、绑定、训练模型或渲染结果。下次对失败场景重新执行 MASK 时才会生效；场景级目标身份不明确或正常帧的提示检查不通过，仍可能报错。

## 实施结果

已同步到 `172.26.14.81:32624` 的 `/root/Fast-PGSR`，部署前确认没有正在运行的项目批处理、分割、训练或渲染进程。旧代码及旧回归文件备份于 `/root/fast-pgsr-setup-only/low-support-tolerance-20261017/backup/`；部署清单和结果记录在同目录的 `update-manifest.json`、`deployment-result.json`。

本机及服务器 Fast-Sam2 环境的上述 CPU 回归通过。对 `A1701-2-R6-0918`、`A70-4-R2-0918` 执行只读 `trained` 校验，均通过；两个场景共8个关键文件（30000次点云、语义状态、strict目标点云、训练输入绑定）的 SHA-256 在更新前后及只读校验后完全一致。

本次没有加载神经网络模型、重新生成真实视频掩码、重新训练、重新导出或渲染。`A1646-2-R4-0918` 的新掩码尚未生成；实际弱支持帧的效果仍需下一次 MASK 执行后检查，不能把 CPU 逻辑回归当作真实重建效果验证。
